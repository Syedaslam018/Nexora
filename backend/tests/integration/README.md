# Integration tests

These hit a **real PostgreSQL database** through Prisma and the actual
Express app (via `supertest`, no HTTP server listening on a port needed —
`createApp()` is passed directly to `supertest`). Unlike `tests/unit`,
nothing here is mocked below the HTTP layer: a request to
`POST /api/auth/register` really inserts a row, `POST /api/orders` really
runs the checkout transaction and decrements real inventory.

## Setup (one-time)

1. Have a disposable Postgres reachable — the simplest option is the one
   `docker-compose.yml` already defines. From the repo root:
   ```bash
   docker compose up -d postgres
   ```
2. Create a **separate database** for tests — never point this at the same
   database as `npm run dev`, since these tests truncate every table
   between test files:
   ```bash
   docker compose exec postgres createdb -U nexora nexora_test
   ```
3. Apply migrations to that test database:
   ```bash
   DATABASE_URL=postgresql://nexora:nexora_dev_password@localhost:5432/nexora_test npx prisma migrate deploy
   ```
   (Migrations themselves are generated by `npx prisma migrate dev --name init`
   against a running Postgres, per `docs/PROGRESS.md`'s Phase 2 notes — this
   environment never had a live database to generate them from.)

## Running

```bash
npm run test:integration
```

`vitest.integration.config.ts` defaults `DATABASE_URL` to
`nexora_test` on `localhost:5432` — export a different `DATABASE_URL` in
your shell first if your test database lives somewhere else.

## How fixtures work

`helpers.ts` exports `resetDatabase()` (truncates every table, called in
each file's `beforeEach`) and small seed helpers (`seedCategory`,
`seedBrand`, `seedProductWithVariant`, `registerAndLogin`) so each test
file builds exactly the data it needs rather than depending on a shared
fixture load order. Files run sequentially, never in parallel
(`fileParallelism: false`), since they share one database.
